# S12 Super Speakers — stage brief (owner decisions 2026-11-07/08)

S12 — "Super Speakers": school-wide English points, scorer PWA, big-screen board (module inside Class Compass, shared DB).

Owner decisions (record as DECISIONS entries + ROADMAP stage S12, honest boxes):
1. Board shows ONLY the top 3 students of the current week, each with FULL name and CLASS name, strongly emphasised (podium). Students with 0 points never shown. When nobody has points yet (e.g. right after the weekly reset) show the friendly placeholder "We are waiting for our super speakers" (TR "Süper konuşmacılarımızı bekliyoruz"); with 1–2 scorers, the empty podium places use the placeholder style. Ties share a rank (dense ranking; if more than 3 students tie for the podium, show all tied students at that place in a compact way — decide and document).
2. Full names.
3. Class totals panel on the board: weekly total per participating class (every class shown, including 0, sorted by total then Turkish collation), so every child contributes.
4. Scorers are teachers the admin grants access via SPECIAL LINKS, independent of whether their account uses Class Compass classroom features. Admin creates a scorer link with a display name and an interface language (English default / Türkçe; the scorer app then opens in that language and the scorer can still switch) (and optionally links it to an existing teacher account), can revoke/regenerate; every award records the scorer link id (+ user id if linked).
5. Positive points only (+1). No negative points.

Server (use npm run new:module -- superSpeakers, the SX manifest pattern, admin module policy key; school-wide, not per teaching context):
- tables: scorer_links (id, label, userId nullable, tokenHash unique HMAC, generation, createdBy, createdAt, revokedAt, lastUsedAt), scorer_pairings (one-time 6-digit pairing codes, hashed, 10-minute expiry, single use, rate-limited), display_links (read-only board links, same token pattern, revocable), point_events (id = opId, studentId, scorerLinkId, userId nullable, occurredAt, localDate, weekStart computed in school timezone at write time, classIdSnapshot + classNameSnapshot, voidedAt, voidedBy, voidReason), super_speakers_settings (weekStartsOn/default Monday 00:00 school tz, participating classes or all active classes of the current school year, undo window minutes default 10, per-scorer rate limit e.g. max 60 awards/10 min, board title/messages {en,tr}, board language, theme key from the theme registry).
- Principals: new access class 'scorer' (session derived only from a scorer link via fragment-token exchange → strict long-lived scorer session cookie, re-validated every request so revocation is immediate) and 'display' (read-only board session from a display link). Register in the access-class enforcement and permission-matrix test. Scorer sessions can ONLY: list participating students (id, full name, class name, folded search key, avatar hue/initials) for search, award +1, undo/void own awards within the window, see their own recent awards. Display sessions can ONLY read the board. Neither can reach any other endpoint (matrix test).
- iOS home-screen web apps use a separate cookie store from Safari, so the cookie set when the link is opened in Safari is NOT available in the installed app. Flow: the link page (/p#<token>) exchanges the token, shows install instructions per platform (Android: install prompt / Chrome menu; iOS: Share → Add to Home Screen, with pictures), and shows a 6-digit pairing code; the installed app (start_url /p/app, standalone) if it has no session asks for the pairing code (or 'open your link again') and exchanges it for its own session. Android Chrome WebAPK shares cookies so it signs in directly. Never put the token in the manifest or start_url.
- Commands via the outbox (idempotent opIds): 'points.award' {studentId} (student must be active and in a participating class; rate limit; double-tap guard client-side 700 ms with 'tap again to add another'), 'points.voidOwn' {eventId} (only own, within undo window). Admin: void any award with reason (audited), list awards with filters.
- Board data: GET board (display or admin access): current week range, top-3 (live events in current week; dense rank; tie handling), class totals, last update time. Live updates via Server-Sent Events endpoint (display access) pushing a version/changed signal; heartbeat every 25 s (Cloudflare idle timeout ~100 s); client refetches on signal; fallback polling every 10 s; auto-reconnect with backoff. Make SSE work behind the Vite proxy in dev and behind Cloudflare Tunnel (no buffering headers: Cache-Control no-store, X-Accel-Buffering no).
- Weekly reset = time window only; history kept; previous weeks queryable (weekly winners history, totals per class/week, per scorer, per student) in S11 reports via the module's report contribution hook, CSV export.
- PWA: web app manifest(s) for the scorer app (name 'Super Speakers', icons generated as PNG at build or committed original SVG-derived PNGs 192/512 + maskable + apple-touch-icon), service worker caching ONLY the app shell (never API data), theme-color, standalone display. Lighthouse-style installability criteria satisfied on Android Chrome.

Scorer app UI (mobile-first, one-handed, EN/TR switch stored on device):
- Opens on a big search field with instant results as you type over the full school list held in memory (Turkish folding via foldForSearch: 'isik' finds 'Işık'; matches given names, family names, any word start, class name like '3a'/'3-A', student number), class filter chips, 'Recent' row of the scorer's recently awarded students, results as large cards (avatar initials, full name, class) each with a huge '+1' button. After award: undo bar (undo window), SaveStateBadge (saving/saved/offline n queued), NeedsAttention tray. Handles 1,500+ students smoothly (virtualise the list if needed; test with 1,500 synthetic students).
- My awards today list with undo for those within the window.

Board UI (/board#<display token> → exchange → /board): full-screen 16:9 big-screen layout readable from the back of a classroom/hall; title 'Super Speakers' (configurable), week range, podium for top 3 (1st largest, centre; full name + class name; avatar initials; points), class totals panel (bars with numbers, never colour only), placeholder message when empty; gentle single-play animation when ranks change (respect reduced motion; no flashing); theme from the theme registry (default explorer or setting); connection indicator subtle; cursor hidden after inactivity; no scrolling needed at 1920x1080 and 1280x720; Turkish characters perfect. No other student names, no zero scores.

Admin UI: Super Speakers page: enable module, settings, participating classes, create/revoke/regenerate scorer links (copy link, QR code, label, optionally link teacher account), display links, award log with void, weekly history.

Tests: weekly window boundaries (property test around Monday 00:00 Istanbul), top-3 dense ranking + ties + zero hidden + placeholder states, class totals include zero classes, idempotent award replay, rate limit, void own within window only, scorer cannot access any non-scorer endpoint (matrix), display read-only, revoked scorer/display link fails immediately, pairing code single use + expiry + rate limit, token never logged, SSE stream sends change signal after award and heartbeats, search folding (Turkish) unit tests, 1,500-student search performance test. E2E: admin creates scorer + display links; scorer (mobile viewport) opens link, searches 'isik', awards +1, undo works; board (1920x1080) shows the podium update live within ~2 s without reload; placeholder after week rollover (clock override in test env).
Finally deploy check is done by the lead on the test VM.
