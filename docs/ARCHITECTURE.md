# Class Compass — Architecture & Data Model

Status: **PROPOSED — awaiting owner decision (D-005).** Full panel review with scoring:
`docs/design/2026-11-07-stack-panel-review.md`.

## 1. Recommended: "Compass Core"

One TypeScript modular monolith, one SQLite database file, one uploads folder, one Linux server.

| Layer | Choice | Why |
|---|---|---|
| Frontend | React 19 + Vite SPA, TypeScript strict, TanStack Router + Query, React Aria Components, Tailwind 4 on CSS-variable design tokens | Accessible touch primitives (no hover dependence), type-safe routes with guards, cache that can be purged on PIN lock |
| Backend | Node LTS + Fastify 5, Zod 4 contracts shared with the client | Validation and *output allow-listing* from one schema; small, well-known |
| Database | SQLite (better-sqlite3, WAL) via Drizzle migrations | Hundreds of students is <1% of SQLite capacity; no DB server to run/upgrade; backup = consistent file + folder; tests run on Windows with zero installs |
| Classroom writes | Command outbox: every action has a client UUIDv7 `opId`, stored in IndexedDB before sending; server dedups in the same transaction | Satisfies UX-10/11, CNT-5: no loss, no duplicates, survives refresh |
| Sync | Lesson-state polling (5 s, ETag/304) while visible | Laptop + touchscreen stay consistent; SSE can be added later |
| Auth | In-house (~500 lines, fully tested): argon2id, server-side sessions, `__Host-` cookies, Origin+header CSRF, CLI-only first admin | Small surface, no deprecated libs, no external IdP |
| Files | Type sniffing + allow-list, images re-encoded (EXIF/GPS stripped), random names outside web root, served only via policy-checked endpoint with sandbox CSP / nosniff | STU-8: uploads can never execute |
| Import/OCR | papaparse, SheetJS (xls/xlsx), mammoth (docx), unpdf (pdf), **tesseract.js local OCR** (tur+eng) in a worker thread | No student data leaves the server (IMP-7) |
| i18n | Typed EN/TR dictionaries (TR must match EN keys at compile time): the main dictionary holds only what the student page shows, the staff dictionary and smaller area dictionaries the rest (D-179, D-182); editable labels stored as `{en,tr}`; one Turkish text module (`Intl.Collator('tr')`, tr-TR casing, NFC) | UX-3/4/5 |
| Charts/print | Recharts (SVG) + data table under each chart; print-specific routes; CSV with BOM and formula-injection escaping | RPT-4/5 |
| Testing | Vitest (unit/integration on real SQLite), fast-check (property tests for rotations, weeks, grouping), Playwright (touch, mobile, PIN bypass attempts, screenshot matrix themes×languages×text sizes), axe | ENG-3/4 |
| Deploy | Caddy (HTTPS) → one hardened systemd service; releases + `current` symlink; pre-migration snapshot; health-check rollback | Two services total |
| Backup | Hourly online `db.backup()` + uploads, nightly encrypted off-site via restic, weekly verify, restore CLI exercised in CI | DAT-4 |

**Multi-school later:** one instance per school (own data dir, subdomain, systemd template unit) — zero risk of cross-school leakage.

### Alternative: "Compass on PostgreSQL"
Identical app, contracts, UI, command model. SQLite → PostgreSQL 17 (Debian package). Gains: Turkish ICU collation in SQL, transactional DDL, optional row-level security for the student portal, ready for one multi-school instance. Costs: a third service to run/upgrade, pg_dump-based backups, PostgreSQL install needed on Windows for tests. **Choose it only if a hosted multi-school service is realistic within ~2 years.**

## 2. Code structure
```
src/shared/      contracts (Zod endpoint registry), i18n dictionaries, turkish text utils, tokens
src/domain/      pure logic, no I/O: rotations, week boundaries, grouping solver, metrics, name parsing
src/server/modules/<module>/{routes,service,repo,policy}.ts
src/client/modules/<module>/   + src/client/ui (design-system components)
```
- Each module (lessons, counters, secret, assistant, grouping, homework, attendance, goals, evidence, links, import, reports, admin) declares a **manifest**: dashboard slots, End-Lesson steps, settings, permissions. Disabled modules simply don't contribute; data stays (CFG-2, LES-3). Implemented in SX (D-069): one server and one client manifest per module, one list file per side, keys from `src/shared/modules.ts`; see `docs/EXTENDING.md`.
- `eslint-plugin-boundaries` stops modules reaching into each other's internals; `tests/client/lint-rules.test.ts` (TypeScript compiler API) bans raw UI strings in JSX, checks en/tr key parity and bans raw colours outside the token sheet.
- **Client shell (S3):** `src/client/router.tsx` (TanStack Router, code-based) → `RootLayout` (locale, text scale) → route guards in `routes/guards.ts` (`requireSession`, `homeFor`, safe `next`). `/classroom` (classroom-safe dashboard: class switcher, banner with local date, save badge, attention tray, module slots), `/teacher/*` and `/admin/*` (both wrapped in `SensitiveGate`: PIN lock screen, menu-first, idle relock, display banner). Admin screens and `/dev/catalog` are lazy chunks (D-038). Server state via TanStack Query; `me` is always refetched before guarded routes and after a 423, and `['sensitive', …]` caches are purged on lock and on bfcache restore.
- **Offline outbox (ENG-4):** `src/client/lib/outbox.ts` stores command envelopes in IndexedDB (Dexie) *before* sending, flushes in order in batches to `/api/commands` (single flight per tab, Web Locks across tabs), retries network/5xx/429/423 failures with exponential backoff (a locked device keeps its queue), pauses on 401 until the next sign-in, and moves rejected commands to a needs-attention list (retry under a new opId, or dismiss; opId conflicts can only be dismissed). The server's opId log makes resends after a lost response harmless. Commands belong to the account that queued them (D-039): only the signed-in owner's commands are sent (with `asUser`, which the server checks) or shown, so on a shared classroom PC another teacher's queued commands stay parked until that teacher signs in again.
- **Admin UI:** one screen per S2 resource under `/admin` (accounts, school settings, years/terms, subjects, classes with theme preview and promotion, teaching assignments, module and media policies, students with search/move/history, audit log). Temporary passwords are shown once with a copy button; destructive actions need typed confirmation.
- Every endpoint is declared once with an **access class** (`public | user | account | classroom | teacher | admin | student | scorer | display | mcp | oauth`, `ACCESS_CLASSES` in `src/shared/contracts/define.ts`; what each one means is in `docs/CONVENTIONS.md` → HTTP API); the server refuses to start if one is missing, and a test enumerates all endpoints against the permission matrix.
- **Origins (S14f, D-157):** `config.origins {main, speakers, mainHost, speakersHost, split}` comes from `PUBLIC_ORIGIN` and the optional `SPEAKERS_ORIGIN`. Unset (the default), Super Speakers stays on the main origin and nothing changes. Set, CSRF checks are by endpoint path (`originClassOf` in `lib/http.ts`: `/api/scorer…` and `/api/board…` accept both origins, every other endpoint only the main one), and an `onRequest` hook (`lib/speakersHost.ts`) limits the speakers host to the scorer app, the board and their APIs, while the main host answers `/p`, `/p/app` and `/board` with a 308 to the speakers origin. Scorer and board links use `origins.speakers`; every other link stays on `PUBLIC_ORIGIN`.

## 3. Permission model
**Principals:** admin, teacher (sessions from login); student (session derived only from a personal link — `student_id` never comes from request parameters).

**Ownership:**
- *Shared class data* — students, enrolments, daily attendance, photos: any teacher with an active teaching context in that class may edit; every change records `changed_by` and an audit event (ACC-7/8/9).
- *Context-owned data* — a **teaching context** = teacher × class × subject. Lessons, counters, routines, assistant rota, Secret Student rounds, groupings, homework hang off it and are visible/editable only by its teacher (and admins) (ACC-10).
- *Student-owned data* — student goals, reflections, self-assessments, evidence: editable by the student (via link) and readable by their teachers. Teacher assessments, feedback and private notes are teacher-owned; students have no write path, and private notes have no student-side read path at all (GOL-3/5/6).
- *Admin* — global module availability, accounts, years/terms, classes/subjects, assignments, maintenance.

**Classroom mode & PIN (PIN-1…9):** classroom mode is a property of the device session, set when a lesson is started/resumed on it. In classroom mode, only `classroom` endpoints work; `teacher`/`admin` endpoints return **423 PIN_REQUIRED** server-side, so URLs, history, refresh and raw API calls can't bypass it. Unlock slides 5 min per sensitive request; relock on entering the classroom view, the lock button, or inactivity; escalating lockout after 5 failures, session revoked after 10. Sensitive client caches are never fetched while locked, purged on lock, and sent `no-store`. After unlock: teacher menu first, with a persistent "visible on classroom display" banner.

## 4. Data model (outline)
One school per instance. Times in UTC; events also store `local_date` and `week_start` computed at write time in the class timezone (default Europe/Istanbul, week from Monday 00:00 — D-003).

- **Structure:** `school_settings`, `school_years`, `terms`, `subjects{name:{en,tr}}`, `classes{year, name, theme, tz?}`, `teaching_contexts{teacher, class, subject, active_from/to}`, `module_policies` (admin), `context_modules{context, module, enabled, config}` (teacher).
- **People:** `users{role admin|teacher, password_hash, pin_hash, locale, text_scale, disabled_at}`, `sessions`, `auth_attempts`, `one_time_tokens`.
- **Students:** `students{student_number?, full_name, name_fold, avatar_hue, photo_file_id?, photo_consent, deactivated_at}`, `enrolments{student, class, year, from, to, reason}` (promotion keeps history), `student_subject_levels` (never shown on classroom screen).
- **Attendance:** `attendance_daily(student,date)` + `attendance_lesson_exceptions(lesson,student)`; effective = exception › daily › *not recorded*. Independent of homework.
- **Lessons:** `routine_templates{stages}`, `lessons{context, status active|ended|abandoned, routine_snapshot, stage_index, timer, reflection, class/subject name snapshots}`; DB-enforced one active lesson per context.
- **Counters:** `counters{kind, labels, scope, segments, reset_period, thresholds}`, `threshold_responses`, `counter_events{id=opId, lesson, student?, week_start, voided_at/by, label_snapshot}`, `threshold_crossings`. Lesson total = live events of that lesson; weekly count = live events in that week (CNT-8).
- **Secret Students:** `secret_rounds{lesson, requested, selected, shortfall_reason, revealed_at}`, `secret_selections{student, status sealed|withdrawn_absent|revealed, outcome, note}`. Only the secret-student service can read identities pre-reveal; DTOs carry counts only. Absent selected student → silently replaced in the same transaction; responses identical either way (SEC-3/7).
- **Assistant:** `assistant_plans(context, week){announced_at}`, `assistant_assignments(context,date){planned, actual, status, reason, absent_student_ids, absence_undo}` — materialised weekly plan, so announced schedules never regenerate; absences carry the turn forward and are recorded per day (D-068).
- **Grouping:** `group_templates{mode level|mixed, count|target_size, seed, groups}`, `pair_constraints{must|must_not}`, `lesson_groupings{effective_groups, unsatisfied}`, `level_lists{class, subject, labels}` (the ordered level list of a class+subject, D-187; teacher-only like the levels).
- **Homework:** `homework{context, title, details, assigned_on, due_on}`, `homework_marks{status, note}` — no row = *Not checked*, never Missing.
- **Goals:** `skill_categories`, `goals{author_type, preset?, review_on}`, `goal_entries{author_type, kind reflection|progress|self_assessment}`, `teacher_assessments`, `teacher_feedback` (student-visible), `private_teacher_notes`, `evidence{kind text|link|file|audio}`, `text_starters{kind, subject?, category?, text{en,tr}}` (sentence starters with a `___` blank, S14d, D-152).
- **Own avatar pictures (S24, D-184):** `avatar_pictures{student, status pending|approved|refused, quarantine_key?, file?, created_at, expires_at?, decided_at?, decided_by?, refusal_reason?}`; waiting bytes in `DATA_DIR/avatar-quarantine/` (outside uploads, so never in backups or exports), approved ones as the student's `files` row; `classes.avatar_uploads` and `super_speakers_settings.show_own_pictures` switch them on.
- **Files:** `files{storage_key, thumb_storage_key?, sha256, size, sniffed_mime, kind image|document|audio|import_source, original_name?, owner_student?, uploaded_by, deleted_at}` (S9, D-076): bytes under `uploads/xx/yy/<uuid>`, served only by `/api/files/:id` after the policy check.
- **Links:** `student_links{student, token_hash (HMAC with server pepper), token_cipher (AES-256-GCM, key from the pepper by HKDF; S13b2, D-115), generation, origin, revoked_at, revoke_kind, last_used_at}`; one permanent link per active student, made automatically, replaced or revoked only in an emergency (D-118); token delivered in the URL fragment then exchanged for a strict cookie, so it never reaches logs or referrers. The student page is its own small client entry (`student.html`, served at `/s`) assembled from the `studentPage` sections of the modules enabled in each of the student's subjects (S10, D-084, D-085): since S14d a home screen of tiles and short-step screens in the query string (D-151), within a gzip size budget checked by the build.
- **Import:** `import_batches{source, file?, target_class, status draft|committed|reverted, columns, mapping, notices, counts}`, `import_rows{raw, page, parsed, edited, ocr_conf, flags, candidates, decision, matched/created ids, fill_number, outcome, revert_outcome}` — enables preview, report and safe reversal (S9, D-078). Parsers live in `server/modules/import/parsers/`, the pure row logic in `src/domain/importing.ts`. A list with several classes is split by its class column first (`splitByClass`, Turkish-aware `classLabelKey`) into one ordinary batch per chosen class, linked by a split id in the batch mapping (S20c, D-171); HTML-table `.xls` lists are read by a text-only scanner in the parser worker.
- **Audit/ops:** `command_log(op_id)`, `audit_events{actor, action, entity, before, after}` (insert-only), `backup_runs`.
- **Notifications (S14e3, D-155):** `notifications{user, student, subject?, context?, category, entity, entity_id, count, local_date, read_at}` (ids only; one row per day for the aggregate categories; 90-day purge) and `notification_digests{user, local_date, status, items}` (counts only), written through `lib/notify.ts` by the notifications module's sink and read with an access re-check. The notification settings are the user setting `notifications.settings`.
- **AI tools (S14h1, D-160, D-161):** `school_settings.mcp_enabled` / `ai_student_data_allowed` / `mcp_token_max_days`, `mcp_tokens{kind pat|oauth, family, client?, user, name, token_hash, prefix, scopes, privacy_mode, expires_at, revoked_at, last_used_at}`, `mcp_pseudonyms{family, student, number}` ("Student N" per token family), `mcp_calls` (method, token, user, outcome, duration, bytes; never arguments) and `audit_events.via_token_id`. The `/mcp` endpoint (`server/modules/mcp/`) has its own access class `mcp` (bearer token only) and serves tools generated from contracts that opt in, through the privacy gate. OAuth 2.1 for AI apps (S14h2, D-160; access class `oauth`, consent page `/oauth/consent`): `oauth_clients{client_id, kind dcr|cimd, name, redirect_uris}`, `oauth_requests` (waiting consent, browser- and account-bound, single use), `oauth_grants` (a connection = one token family: scopes, privacy mode, expiry), `oauth_codes` and `oauth_refresh_tokens` (HMACs only), `school_settings.oauth_redirect_hosts_json`.
- **Assistant connections (S19a, D-179):** `ai_connections{owner_user (null = school), type, name, base_url, local_network, models_json (with per-model test marks), secret_cipher (sealed), secret_set_at, secret_source, monthly_token_budget, daily_message_limit, enabled, kvkk_confirmed_at/by, deleted_at}`, `ai_connection_usage{connection, user, local_date, messages, input_tokens, output_tokens}`, `ai_connection_settings{default_connection_id, default_model, teacher_connections_allowed}` and `ai_oauth_states` (HMAC of the state, sealed PKCE verifier, single use, 10 minutes). Module `server/modules/aiConnections/` (adapters for Anthropic, OpenAI Chat Completions and Gemini behind `streamChat`).
- **Assistant chat (S19b, D-180):** `assistant_chats{owner_user, title, connection, model, summary, summary_seq, next_seq, last_message_at, archived_at}`, `assistant_messages{chat, seq, role user|assistant|tool, content (as sent: pseudonyms while student data is off), tool_calls_json (with each call's state: auto, pending, approved, declined, refused, expired), tool_call_id, untrusted, privacy, status, error_code, tokens}` and `assistant_settings{enabled, retention_days}`. Module `server/modules/assistantChat/` (the agent loop over `streamChat`, runs streamed as Server-Sent Events, confirmation of changes, compaction, retention) uses the AI tools layer through `server/modules/mcp/assistant.ts` (tools, privacy filter, names back for the browser). Client: the lazy page `client/modules/assistantChat/` (teacher area only).
- **Themes (S14g, D-158):** `custom_themes{key, package_json (exactly as validated), report_json, status draft|enabled|disabled, bytes, created_by/updated_by, created_at/updated_at}` holds the theme packages administrators import (at most 30). `classes.theme` and the Super Speakers theme are open slugs (a built-in key or a package key): services check a changed theme with `assertThemeUsable` and send `effectiveTheme` to screens, so a disabled package shows the default theme while the stored choice is kept.
- **Personal settings:** `user_settings{user, key, value}` and `report_views` (S14e1), `classroom_layouts{user, scope 'all'|context, layout_json, version}` (S14b, D-148: each teacher's classroom board layout, validated on write and read, not audited).
- **Renames (DAT-6):** historical rows keep label snapshots, so renamed classes/goals/counters stay understandable.

## 5. Design system
Theme registry (SX, D-070): each theme in `src/client/themes/<key>/` is a complete `ThemeDefinition` (colour tokens, typography, shape, avatar, icon style, decoration and pattern, illustrations, mascot poses, one-shot motions with reduced variants, optional sounds). Semantic tokens (`--cc-surface`, `--cc-accent`, `--cc-level-0..3`…) are generated as one `[data-theme]` block per theme; `app.css` holds component rules only. Components only use semantic tokens and theme slots; themes change appearance only. Meanings (icons, labels, positions) identical across themes. Text scale is a root multiplier; reduced-motion and per-class sounds/animations switches gate every effect; no repeated flashing anywhere.
