- GRP-1 change: default is FOUR grouping options per class/subject (replacing five arrangements): Lions and Eagles = level-based (differentiated), Dolphins and Tigers = mixed-level. Each option arranges present students into Group 1–5 (default 5 groups; group count/target size still configurable; number and type of options still configurable).
- CLASS LANGUAGE, PER CLASS (owner: "generally remove Turkish, but make it optional — broader, from group names etc." → "class based, not school wide" → "Turkish should also be [able to be] the main language, and English off"): replace the school-wide idea with two CLASS settings: `mainLanguage` ('en' | 'tr', default 'en') and `secondLanguageEnabled` (boolean, default false). This gives four modes per class: English only (DEFAULT), Turkish only, English main + Turkish, Turkish main + English. Editable by admins and by teachers of that class. It governs everything class-facing for that class: classroom display language and all built-in UI text on it, the class's students' personal pages, quote-of-the-day language, seeded defaults for that class's contexts (group/option names, counter labels and threshold messages, routine stage names, assistant responsibilities, skill categories, goal presets, homework status labels), and the label editors for that class's contexts (show the main-language field as required and the second-language field only when enabled; a language that is off is never shown). The language switch on the classroom display/student pages appears only when a second language is enabled. Existing {en,tr} data is kept untouched (nothing deleted) and reappears when that language is enabled again. Missing translation in the active language → fall back to the other stored language, flagged in the teacher's editor as 'needs translation'. The teacher's own interface language stays a personal profile preference (default English) because it is not class-facing; admin pages are not class-bound. ACCOUNT CREATION: when an admin creates a teacher (or admin) account, the create form has a required 'Interface language' choice (English / Türkçe, default English) stored as users.locale, so the new teacher's first sign-in, forced password change and PIN setup appear in that language; admins can also change it later on the user edit page; teachers can still change their own afterwards. Super Speakers scorer links (S12) get the same language choice. Tests: account created with Turkish shows Turkish on first sign-in / password change; changing one user's language never affects another. The Turkish-reminder COUNTER is a feature, not a language: its boxes on student cards are hidden by default with a per class/subject toggle to show them (and its labels follow the class language; in Turkish-only classes it is just another counter). Turkish NAME handling (Turkish collation, İ/ı casing, folding, e-Okul import) is unaffected and always on. Tests: English-only class renders no Turkish UI strings on its display/student pages; Turkish-only class renders no English UI strings there (sample scan of known strings) and its editors have no English inputs; bilingual modes show the switch and both fields; two classes with different modes are isolated; switching modes never deletes label data.
- Delete students: three levels — teachers can remove a student from a class (enrolment ends, history kept); admins deactivate; admins can PERMANENTLY DELETE (erases the student and all their records/files everywhere — also the KVKK erasure path; typed confirmation; audit keeps only a non-identifying 'student erased' entry with counts).
- Teachers can change the theme of their own classes (from the teacher class settings); creating classrooms stays admin but must be easy to find (admin home quick action + empty-state call to action).
- Weather: Open-Meteo (free, no key, only coordinates sent), server-side fetch with caching (30 min) and a 5 s timeout; school location configurable in admin school settings, default 'Ankara, Kızılay' (latitude ≈ 39.92, longitude ≈ 32.85 — verify sensible coordinates for Kızılay, Ankara). If the server has no internet (the test VM), the widget hides quietly. Child-friendly weather display (icon + temperature + short word), theme-aware, no colour-only meaning.
- Time's-up voice: default browser speechSynthesis English voice saying "Time's up! Time's up!" (pick an en-* voice; fall back to a theme chime if none); optional teacher-recorded clip (recorded in the teacher area via MediaRecorder, stored as a teacher asset — not student media, so media.* student flags don't apply; still validated/sniffed/size-limited).

2) GROUPING REDESIGN (matches the teacher's mock-up: option buttons with animal icons, Shuffle, colour cards 'Group N' + icon + member count, member rows): classroom screen 'Groups' button opens a FULL-SCREEN group screen (not inline expansion) with: option buttons (Lions, Eagles, Dolphins, Tigers by default — original theme-aware icons, meaning never depends on emoji or colour), Shuffle (new seed for the current option, with undo), the group cards (Group 1..5), and the classroom timer embedded. Move students: tap a student then tap a target group (touch-first) plus drag-and-drop; moves apply to the current lesson grouping immediately; 'Save to option' updates the saved option. Absent students excluded for the lesson. NO levels or 'differentiated' labels on the classroom screen; level editing ONLY in the teacher area (PIN), which has the same editor plus a levels column. Per-class display option: names in Turkish-correct upper case (toLocaleUpperCase('tr-TR')) as in the mock-up; default normal case. Uneven sizes handled; constraint conflicts reported in the teacher area only. Existing contexts keep their old arrangements (history) and get a one-click 'Use the 4 default options'; new contexts get the four options.

5) SIZE/DENSITY: visible size control (Compact / Normal / Large, remembered per device+teacher) on the classroom screen and teacher area, plus automatic fit: the main dashboard fits without scrolling at 1440x900 and 1470x956 (MacBook Air), 1366x768, 1280x800, 1920x1080, 2560x1440 and a 4K touch panel at 150–200% scaling; the student grid auto-sizes to fit 18–20 students without scroll at Normal on 1440x900; text scale preference still applies. ===== S13b — Theme engine v2 (sounds, music, celebrations), quote of the day, weather, timer voice, importer sheet choice, deleting students, teacher class themes
1) THEME ENGINE v2: extend the SX theme definition with a sound pack (events: tap, undo, stageChange, timeUp, thresholdReached, assistantCheck, groupShuffle, secretDrumroll, secretReveal, fanfare, clapping, fireworks, pointAwarded for S12) — each synthesised in code with WebAudio (original) OR CC0 files with source + licence recorded in docs/ASSETS.md; short synthesised music cues (dramatic reveal: drumroll noise envelopes + timpani + brass-like oscillators; fanfare); choreographed sequences: secretReveal = 3-2-1 countdown (big numbers in theme style) + drumroll + cards revealed one by one + fanfare; celebration = clapping + full-screen mascot 'celebrate' pose ~2.5 s + fireworks (canvas particles in theme colours) then back. Reduced-motion variants (no particles, static mascot, soft chime); per-class volume/mute + animation switch respected everywhere; never repeated flashing. SoundManager with volume, mute, unlock on first interaction (autoplay policy), preloading, priority/ducking so sounds don't pile up. Wire sounds into many actions: counter tap, undo, stage change, attendance tap (soft), group shuffle, assistant check, timer end, secret reveal, celebration, threshold.
2) docs/THEMING.md (agent-oriented, comprehensive): anatomy of a theme (tokens, typography, shape, backgrounds, illustrations, mascot poses, motions, sound pack, sequences), step-by-step creation with the scaffold, quality bar (contrast, motion safety, loudness normalisation, licence rules), how tests validate a new theme, a worked example. EXTENDING.md points to it. Optionally add a 4th theme 'space explorers' built by following the guide (only if time allows; mark honestly).
3) QUOTE OF THE DAY: curated list (at least 120) of short, positive, age-appropriate sayings for primary pupils in simple English (original wording or clearly public-domain; attribute only when certain; no copyrighted quotes), a Turkish list of equal quality (original wording) used for classes whose main language is Turkish or with Turkish as second language; deterministic per local date per class; teacher can turn it off.
4) WEATHER: server module fetching Open-Meteo current weather for the configured coordinates (default Ankara, Kızılay), cache 30 min, 5 s timeout, never blocks the page; classroom widget with child-friendly theme-aware icons, temperature in °C and a simple word ('Sunny', 'Rainy'…); hides when unavailable; admin setting for location (label + lat/lon) and on/off.
5) TIMER VOICE: on time up, say "Time's up! Time's up!" via speechSynthesis with an English voice (fallback chime); optional teacher-recorded clip (teacher area: record, preview, save, delete; stored through the uploads pipeline as kind 'teacher_sound', sniffed and size-limited); per class choice voice/clip/chime/off.

7) DELETING STUDENTS: teacher 'Remove from this class' (ends enrolment, keeps history); admin deactivate (exists); admin 'Permanently delete student' erases the student, enrolments, events, marks, goals, evidence, files on disk, links, and anonymises import rows referencing them; typed confirmation; dry-run summary of what will be erased; audit entry without personal data; tests prove nothing identifying remains (scan DB + uploads).

9) ACCOUNT INVITE LINKS + OPTIONAL EMAIL-LINK SIGN-IN FOR TEACHERS (owner request 2026-11-07: "make login by email link possible for teachers by choice when they get their account link, instead of passwords"):
- Account creation becomes an INVITE: admin creates the account (name, email, role, interface language) and gets a single-use invite link (valid 7 days, token hashed with tokenHash, revocable, regenerable) which is emailed automatically when SMTP is configured and can always be copied/shown as QR by the admin. The temporary-password flow stays available as a fallback option for admins.
- The invite page (in the account's interface language) lets the teacher choose their sign-in method: (a) password (set it here) or (b) email link (no password; requires a verified email and SMTP configured — option hidden/disabled with an explanation when SMTP is not configured). Opening the invite proves the email address. The teacher then sets their classroom PIN (still required for classroom mode; email-link sign-in does not replace the PIN).
- Email-link sign-in: login page has 'Email me a sign-in link' (shown only when SMTP is configured); always answers the same neutral message (no account enumeration); rate-limited per IP and per account; link single-use, valid 15 minutes, hashed; the email ALSO contains a 6-digit code so a teacher who requested on the classroom PC but reads email on a phone can type the code on the requesting device (code bound to that pending request, 5 attempts max). The link landing page requires a button press (POST) to complete sign-in, so email security scanners that pre-fetch links cannot consume or use the token. New sign-in session as today (idle/absolute expiry); audit login method.
- Teachers can switch method later in their profile (re-authenticate first: current password, or a fresh email link/code); switching to email-link clears the password hash; switching to password sets one. Admin can see each user's method and can reset it (send new invite). Accounts with email-link only cannot be signed in if SMTP is later disabled → admin warning on the Maintenance page and the admin can issue a new invite with password.
- Owner: 'sign in by email will always be an option' — on every invite and in every teacher profile the email-link method is always offered (production will have SMTP; owner supplies credentials at deployment). Only when SMTP is genuinely not configured (dev/test VM) is it shown disabled with an explanation. Admin accounts: keep password sign-in required — document in DECISIONS.
- Tests: invite single-use + expiry + revoke; choosing email-link removes password sign-in for that account; magic link single-use + 15 min expiry + GET does not consume (POST required); code path on another device; rate limits; no enumeration (same response/time for unknown email); disabled when SMTP not configured; method switch requires re-auth; audit entries; e2e with a fake mail transport (capture the email, follow the link/code).
