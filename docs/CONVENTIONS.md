# Engineering Conventions (read before changing code)

These patterns are established in S0/S1 and every stage must follow them. If a pattern must change, record it in DECISIONS.md and update this file.

**Adding a module or a theme:** follow `docs/EXTENDING.md` (checklists, plus `npm run new:module -- <key>` and `npm run new:theme -- <key>` scaffolds; D-069, D-070). Agents start with the root `AGENTS.md` (D-159).

## Runtime & tooling
- Node 26 runs TypeScript directly (type stripping). **Only erasable TS syntax**: no `enum`, no `namespace`, no constructor parameter properties. Use `as const` objects and union types.
- Relative imports include the `.ts`/`.tsx` extension. `import type` for type-only imports (`verbatimModuleSyntax`).
- `npm run check` = typecheck + lint + tests. It must be green before every commit. `npm run build` must succeed.
- Commit messages: `<stage>: <summary>` and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Layout & boundaries (lint-enforced)
- `src/shared` — contracts (Zod endpoint definitions), i18n, Turkish text utils. Imports only `shared`.
- `src/domain` — pure logic (rotations, week math, grouping solver, metrics, name parsing). No I/O. Unit + property tests (`fast-check`).
- `src/server/modules/<module>/{manifest,routes,service,repo?,policy?,commands?}.ts`. The module's `manifest.ts` (`defineServerModule`) is the only place that wires routes, commands, lesson hooks and config, and it is listed once in `src/server/modules/index.ts` (D-069). The client mirror is `src/client/modules/<module>/manifest.tsx`, listed in `src/client/modules/index.ts`. Module policy keys come from `src/shared/modules.ts` only.
- `src/client/...` — React. Never imports server code.

## Database
- Tables in `src/server/db/schema.ts` (append a section per module). Conventions are in the file header: UUIDv7 text ids (`newId()`), epoch-ms UTC `...At`, local dates as `'YYYY-MM-DD'` text computed in the class timezone, `{en,tr}` JSON for teacher-editable labels, soft archive/void instead of delete.
- After schema changes: `npm run db:generate -- --name <stage_desc>` and commit the SQL in `drizzle/`. Never edit an already-committed migration. Check generated SQL: SQLite table rebuilds must not cascade-delete data.
- Writes that must be atomic use `tx(db, fn)` (synchronous; never `await` inside).
- Names are sorted in application code with `sortByName`/`compareNames` (never `ORDER BY name`).

## HTTP API
- Every endpoint is declared once in `src/shared/contracts/<module>.ts` with `endpoint({method, path, access, input, output})` and registered with `route(app, deps, ep, handler)`. Output schemas are allow-lists: never return rows directly when they contain fields the caller must not see.
- Access classes (`define.ts`, `ACCESS_CLASSES`): `public | user | account | classroom | teacher | admin | student | scorer | display`. `scorer` and `display` (S12, D-128) are Super Speakers link sessions with their own cookies; take the link from `requireScorer(ctx)` / `ctx.display`, never from the request. Classroom-safe actions (taps, attendance, stage changes) are `classroom`; anything showing reports, private notes, roster edits, settings, links is `teacher`/`admin` (PIN-gated in classroom mode server-side).
- Resource authorisation is done in services with policy helpers (e.g. "teacher owns this teaching context", "teacher teaches in this class"). Never trust ids from the client without checking ownership. Student principals get `studentId` from the session only.
- Temporary passwords (D-040): an account with `mustChangePassword` can only use `user` endpoints and endpoints declared with `allowWithTemporaryPassword: true` (the password change). Do not add that flag to anything else.
- Errors: throw `AppError(code, message, details?)`. Stable codes in `ErrorCodes`. Put a machine-readable `details.reason` (e.g. `YEAR_ARCHIVED`, `POSSIBLE_DUPLICATE`) on business conflicts and add a matching `error.<REASON>` i18n key.
- **School policy helpers** (`src/server/modules/school/policy.ts`) — reuse them, never re-implement: `assertTeachesClass(ctx, classId)` (teacher has an active context in the class), `assertOwnsContext(ctx, contextId)` (returns the context; ACC-10), `assertYearWritable(db, yearId)` / `assertClassWritable(db, cls)` before **any** write touching a class or year (archived = read-only, DAT-1; `isClassWritable` when one of several classes must be writable), `todayFor(deps, cls)` for local dates in the class timezone. Enrolments are date-aware (D-027): use `enrolmentActiveOn(date)` (fromDate <= date < toDate) for "who is in this class on day D" — never `toDate IS NULL` alone — and `defaultEnrolmentDate(deps, cls)` for new enrolments.
- **Module gating** (`src/server/modules/school/modules.ts`): `isModuleEnabled(db, contextId, module)` / `assertModuleEnabled(...)` before serving or accepting module data; `getMediaPolicy(db)` before accepting photo/audio/document uploads (D-014, D-026). Disabled modules keep their data.
- **Uploads and files** (S9, D-076): an endpoint whose body or response is not JSON (multipart upload, file download) is still declared with `endpoint()` and registered with `rawRoute(app, deps, ep, handler)` from `lib/http.ts`: access is checked before the body is read and the input comes from path + query only. Take uploads only through `ingestUpload(ctx, req, { kind, ownerStudentId })` (`modules/files/service.ts`): streamed size limit per kind, content sniffing against `ALLOWED_MIME` (never the client's type or name), image re-encoding, quotas in the insert transaction, audit. Check media flags with `assertMediaAllowed` first. Never serve upload bytes from anywhere but `sendFile()` after `assertCanReadFile()`; never put a storage key or path in a response.
- **Student photos** (D-077): never send `photoFileId` to the client; build the URL with `photoUrlOf(student, getMediaPolicy(db).studentPhotos)` (null unless photos are on, consent is recorded and there is a photo), and render it with `Avatar photoUrl=… photoAllowed=…`.
- **Students**: create via `createStudentInClass` (students service) so names are normalised, duplicates flagged and enrolments opened consistently (teacher, admin, seed, importer). Modules that must act on every new student register with `onStudentCreated(listener)` from the students service (runs inside the creating transaction, synchronous; the links module uses it to give each student a permanent link, D-115). Classroom endpoints return only `id, fullName, initials, avatarHue`; levels and numbers are teacher-access only (GRP-7).
- Optional services (mail) are injected through `AppDeps` (`deps.mailer`) so tests can pass fakes.
- Classroom mutations that must survive flaky Wi-Fi go through **commands**: declare them with `command({...})` in the module's `commands.ts`, export them as a list and put the list in the manifest's `commands` (only manifests register commands, test-enforced; D-069). Handlers are synchronous, run inside the transaction, re-verify ownership and lesson/context consistency, and may use `meta.opId` as the id of the row they create.
- Important edits write `audit(db, ctx.actor, {...}, ctx.now())` in the same transaction (never include secrets or pre-reveal Secret Student identities).
- Time: use `ctx.now()` (injectable clock), never `Date.now()` in services.
- **Lesson-scoped commands** (S5, D-044): a command that records something in a lesson carries `contextId` + `lessonId` in its payload (and the outbox envelope). Resolve the lesson with `lessonForCommand(ctx, payload, meta)` from `modules/lessons/service.ts`; it throws `WRONG_LESSON` / `LESSON_ENDED`. Change lesson rows only through `updateLesson` (bumps `version`, which feeds the polling ETag). Attendance writes go through `setDailyCore` / `setExceptionCore` (roster check + audit).
- **Module hooks into lessons** (D-051, D-052, D-069): modules declare End Lesson steps with `endLessonStep({key, order, module, input, apply})` in their server manifest's `endSteps` (runs inside the end transaction; order < 100 runs before the core reflection; `module` must equal the manifest's `policyKey`) and the matching screen with `endStepUi({...})` in the client manifest's `endSteps`. Dashboard slots (regions `stage` / `actions` / `panels`) and Start Lesson steps (each adds its part of the one `lesson.start` command through `useContribution`) go in the client manifest's `dashboardSlots` / `startSteps`; screens read them through `src/client/modules/registry.ts` and never name a module. Orders are unique per list. Never render a placeholder for a module that has not declared anything.
- **Lesson close and attendance hooks** (D-067): a module that must react when a lesson ends or is abandoned lists the hook in its manifest's `lessonCloseHooks`; one that reacts to attendance lists it in `attendanceListeners`. Both run inside the writing transaction, so keep them synchronous and small. Small per-context module settings are declared as the manifest's `config: { schema, defaults }` (Zod), are validated on every write (`setContextModule` and `mergeModuleConfig`, `INVALID_MODULE_CONFIG`) and services read them with `moduleConfig(db, contextId, module)` (`modules/school/modules.ts`; defaults replace invalid stored values), not with `getModuleConfig` and not in new tables. A settings screen is the client manifest's `settingsPanel`.
- **Grouping boundary** (D-073, GRP-7): levels, arrangement modes, pair rules, their notes and unsatisfied-rule details (and their count, S13a) are teacher-access only. Classroom responses about groups carry names, icons, members, roles and member counts only. A new classroom GET must keep `tests/server/grouping.test.ts` (marker-string scan of every classroom GET) green.
- **Idempotent REST batches** (D-074, D-075): a non-lesson write that may be retried and undone (homework marks) takes an optional client `batchId` (UUID). A repeated batch is replayed, not applied twice. Each change row stores before/after values under the batch, so `…/undo {batchId}` can restore it and skip rows changed since.
- **Secret Student boundary** (D-064): only `server/modules/secret/` may import or query `secretSelections` (test-enforced). Before the reveal, any value it returns, audits, logs or puts into an ETag stamp must be a count. A new GET endpoint is automatically included in the differential leak scan (`tests/server/secret-leak.test.ts`), so keep that test green and do not exempt routes from it.
- **Student link sessions** (S10, D-084): `student` endpoints see ONLY the student cookie (`ccs` / `__Host-ccs`) and every other access class sees only the teacher/admin cookie (`contextFor`), so a browser holding both never mixes them. Take the student id from `requireStudent(ctx).studentId`, never from the request, and scope reads with `studentScope(deps, studentId)` (`modules/links/scope.ts`: classes the student is in today, their active contexts). Someone else's record answers 404; the student's own record written by a teacher answers 403 `NOT_YOUR_CONTRIBUTION`. Student-visible files are served only by `/api/student/files/:id` through `assertCanReadFile` (own upload, or a file on the student's own live evidence). Responses to students carry no author ids, private notes or other students.
- **Student page sections** (S10, D-085): a module adds a section to the personal student page with its server manifest's `studentPage: [{ key, order, build(ctx, { studentId, context, cls }) }]`; `key` and the returned shape must be a member of the shared `StudentPageSection` union (`shared/contracts/goals.ts`, an allow-list), and the screen is registered in `src/client/student/sections.tsx` (type-checked: every key needs one). The links module calls only the contributions of modules enabled for that class+subject.
- **Private teacher notes** (GOL-6, D-086, D-114): only `server/modules/goals/private.ts` reads or writes `private_teacher_notes` (plus the boolean history check and the full-export rows `exportablePrivateNotes` in `goals/history.ts`), and only the teacher Goals service imports it (test-enforced in `tests/server/goals.test.ts`, which also scans every student response for a note). Only the admin's full export includes notes; the per-student export never does.
- **Report sections and timeline** (S11, D-091): a module adds a report section through its manifest's `reports` and student-timeline events through `timeline` (see EXTENDING). Cells come only from `modules/reports/cells.ts`: every count carries its denominator, "not recorded" / "absent" / "not in the class" are their own cells (never 0, RPT-5), no overall score. Reports are `teacher` (own contexts via `reportableContext`, an ended assignment limited to the days it was held by `heldPeriod`; 423 while locked) or `admin` (no lesson reflection notes, usage report without student data). CSV goes through `tableCsv` (BOM, formula escaping) and is audited.
- **Report views and user settings** (S14e1, D-153): a report section declares its tables in its contribution's `meta` (EXTENDING); views (built-in in `shared/reportViews.ts`, saved per account in `report_views`) travel as the report's `sections` parameter, and screens link to a report with the deep-link parameters `contextId`, `studentId`, `view`, `period`, `from`, `to` (`linkSearch` in `reports/ReportsPage.tsx`). Preferences that follow an account across devices are user settings: declare the key once in `USER_SETTINGS` (`server/lib/userSettings.ts`, a Zod schema and a default) and read/write only with `getUserSetting` / `setUserSetting` (invalid stored values fall back to the default). Never put student data or secrets in a user setting; per-device conveniences stay in `localStorage`.
- **Downloads** (S11): a file response (CSV, export ZIP) is a `rawRoute` whose input comes from path + query; the client links to it with `urlFor(endpoint, input)` from `lib/api.ts`, never by building the path by hand. Exports are written to `DATA_DIR/exports/` under a random token and deleted after one download or an hour.
- **Operations boundaries** (S11, D-089, D-090, D-094): backups, restore and off-site copies live in `src/server/ops/` and are driven by the CLI and the maintenance module; backup commands never migrate (only start-up and `migrate` do) and restore refuses a database another connection holds (`databaseInUse`); only `ops/restic.ts` runs restic, with a filtered environment, and every text from it passes `redact()`. Storage credentials come from the environment only and are never logged, stored or returned. Generic exports never name `secret_selections` or `private_teacher_notes`: they use the owning module's helpers (`exportableSelections`, `privateNotesCount`, `exportablePrivateNotes`). Encrypted secrets (`…_cipher` columns, e.g. `student_links.token_cipher`) are blanked like `…_hash` columns; encrypt with `sealSecret(pepper, purpose, aad, text)` from `lib/crypto.ts` (own HKDF purpose per use, the row id as AAD), never with an ad-hoc key. Destructive admin actions need a typed confirmation and an audit row; maintenance actions also need the admin's PIN.
- **Link sessions for scorer and board** (S12, D-128, D-129): new link-based principals follow the student-link pattern: fragment token, HMAC lookup (`tokenHash`), encrypted copy (`sealSecret` with its own purpose), one exchange endpoint (rate-limited, refused attempts counted per address) that sets a strict HttpOnly cookie, and a resolver (`setScorerResolver` / `setDisplayResolver` in `lib/http.ts`) that re-checks the link on every request. Put new secret body fields under a redacted name (`token`, `code`, `pin`, `password`).
- **Super Speakers origin** (S14f, D-157): the scorer app and the board may run on `SPEAKERS_ORIGIN`. Their endpoints must live under `/api/scorer…` or `/api/board…`: `route()` gives those paths the `speakers` origin class (main or speakers origin accepted), every other path only the main origin; never check origins by hand. Build scorer and board addresses from `config.origins.speakers` (everything else from `PUBLIC_ORIGIN` / `origins.main`). Decide which host a request is for with `isSpeakersHost(origins, req.headers)` (the raw `Host` header), never with `req.host` / `req.hostname`, which follow a client-supplied `X-Forwarded-Host` behind a trusted proxy. A new page or file the scorer app or board needs on the speakers host goes into the allow-list in `lib/speakersHost.ts` (and a page the main host should forward into its 308 list), with a case in `tests/server/speakers-origin.test.ts`.
- **School-wide modules** (S12, D-127): a module that is not switched per class+subject goes into `SCHOOL_MODULE_CATALOG` (`shared/modules.ts`); gate it with `isModuleAvailable(db, key)`, never `isModuleEnabled(db, contextId, …)`. It has no per-class `config`.
- **Server-Sent Events** (S12, D-134): a stream is a `rawRoute` that calls `reply.hijack()`, writes `text/event-stream` with `Cache-Control: no-store, no-transform` and `X-Accel-Buffering: no`, sends a heartbeat comment under 100 s, re-checks the session before every push, closes on `req.raw` `close` and registers its close function for the server's `onClose`. Send only a change signal (a version), never data; the client refetches the normal GET.
- **Theme keys** (S14g, D-158): a theme key is a built-in key or the slug of an imported theme package (`Theme` in `contracts/school.ts`). Before writing a changed theme call `assertThemeUsable(db, key)` and when sending a stored key to a screen use `effectiveTheme(db, key)` (both in `modules/themes/service.ts`); never read `custom_themes` elsewhere. Theme packages are checked only with `validateThemePackage` (`shared/themePackage/validate.ts`).
- **Conditional GET** (D-045): an endpoint that is polled sets an `ETag` header and answers `reply.code(304).send()` to a matching `If-None-Match` (see `modules/lessons/routes.ts`); the client polls it with `callConditional(ep, input, etag)`.

## Client
- Data via TanStack Query + `call(endpoint, input)` from `src/client/lib/api.ts`; files go up with `upload(endpoint, input, file)` (multipart field `file`, input in path/query). Sensitive queries use keys starting with `['sensitive', ...]` and are removed on lock.
- All UI strings via `useI18n().t('key')`; add keys to BOTH `src/shared/i18n/en.ts` and `tr.ts` (type-checked). Teacher-editable labels use `pickText(label, locale)`.
- Colours only via semantic CSS variables (`var(--cc-...)`); never raw hex in components. Theme differences (art, mascot poses, illustrations, motion, sounds, typography, shape) come from the active theme through `useTheme()`, `<Mascot>`, `<ThemeIllustration>`, `useThemeMotion()` and `useThemeSound()` (`src/client/themes`); components never branch on a theme key (theme lint, D-070). Status is never conveyed by colour alone (icon/text too). Touch targets ≥ `var(--cc-touch)`. No hover-only affordances.
- Respect `prefers-reduced-motion` and the per-class motion/sound switches; no repeated flashing. Theme animations play once; under reduced motion only their opacity-only `reduced` variant plays (class `cc-motion-reduced`), and nothing plays with the class animation switch off (D-070).
- **Build screens from `src/client/ui`** (Button/BigButton/IconButton, TextField/Select/Toggle, Modal/ConfirmDestructive, Tabs, StudentCard/StudentGrid/CounterBar/MetricCell, ClassBanner/DisplayBanner/ClassSwitcher/DataTable/PanelHead, PinPad, ThemePicker, Toaster/SaveStateBadge/NeedsAttentionTray/EmptyState/Alert). New shared pieces go there and into `/dev/catalog` with fictional data from `src/client/dev/fixtures.ts`. Use the native `Select` for choices (D-036); destructive actions use `ConfirmDestructive` (type-to-confirm for accounts and archives). Admin and teacher tables pass `stack` to `DataTable` (one card per row below 52rem, D-138; a column's `stackRole` makes it the card's heading or leaves it out of the card, D-140); a reversible serious action (archive, deactivate) uses the `danger-outline` button and only what cannot be undone is solid `danger`.
- **Imported themes (S14g, D-158).** Package art is drawn only through the shared SVG sanitiser and `themes/SvgTree.tsx` (`createElement`, allow-listed props), never as markup or with `dangerouslySetInnerHTML`; a package never brings CSS (presets, hex colours and numbers only). List themes for a choice with `pickerThemes()` / `ThemePicker` (built-in plus enabled packages), show a theme's name with `useThemeLabels` / `useThemeName` (an imported theme has its own `{en,tr}` names, not i18n keys), and resolve a key with `themeOf` (unknown keys fall back to the default). Limits live in `shared/themePackage/limits.ts`; after changing tokens, presets or limits run `npm run docs:theming` (drift-tested).
- Component colours (D-070): tokens are defined in TypeScript, in `src/client/themes/base.ts` (shared defaults and derivations) and each theme's `tokens.ts`, the only files where colour literals are allowed. `installThemeStyles()` generates one complete `[data-theme]` block per theme. A new token goes into `COLOR_TOKENS` (`themes/types.ts`) and every theme gets a value; if it is text or UI on a surface, add its pair to `CONTRAST_PAIRS` (`themes/contrast.ts`). `styles/app.css` holds component rules and layout-only variables, and uses only `var(--cc-*)`. Literal colours anywhere else, and unknown `--cc-*` names, fail `tests/client/lint-rules.test.ts`.
- **Routes** are code-based in `src/client/router.tsx`. Teacher-area pages contributed by modules are the manifests' `teacherPages`, served by the single `/teacher/$page` route; link to them with `<Link to="/teacher/$page" params={{ page: 'counters' }}>`. Signed-in routes use `beforeLoad: requireSession` (fresh `me`, redirects to login / forced password change). Everything a teacher or admin sees outside the classroom goes inside `SensitiveGate` (via `TeacherLayout` / `AdminLayout`): it shows the PIN lock screen when locked, enforces "teacher menu first" after unlock and runs the client idle relock (D-032). Never compare `pinUnlockedUntil` with the client clock; use `me.pinUnlocked`.
- Copy text only with `copyText` (`lib/clipboard.ts`; works without https through a fallback) and, when it fails and the text is not on screen, show it with `showManualCopy` (D-140). Never call `navigator.clipboard` directly.
- Toasts are cleared when the teacher area locks, on entering the classroom and on sign-out. Toasts raised from classroom-safe screens (S5 taps, their undo toasts) pass `scope: 'classroom'` so they survive a relock; everything else is treated as sensitive (PIN-3, D-041).
- Mutations from screens: `const run = useRun(); run(() => call(...), { success: t('toast.key'), invalidate: [KEY] })` — it shows the success/error toast (`errorText` maps `error.*` / `details.reason` keys) and invalidates queries. Error reasons the UI must explain get a `details.reason` on the server and an `error.reason.*` key in both dictionaries.
- Classroom writes that must survive flaky Wi-Fi go through the outbox: `getOutbox().enqueue(type, payload, { lessonId, contextId })` (it belongs to the signed-in account and throws when nobody is signed in, D-039; command rejections need a `details.reason` + `error.<REASON>` key so the tray can translate them), register a translated description with `registerCommandDescription(type, (op) => text)` and the queries to refresh with `registerInvalidation(typePrefix, (op) => keys)`. Show `OutboxSaveBadge` and `OutboxAttentionTray` on screens that enqueue (D-035).
- Lesson writes from the classroom: `sendLessonCommand(type, payload)` (`modules/lessons/lessonClient.ts`) enqueues with the lesson and context; apply the change optimistically first with `patchLesson` / `patchRoster`, then queue the command in the same synchronous step: call `getOutbox().enqueue(...)` before awaiting anything (cancel lesson reads after it), so the outbox counts it as pending while its change is on screen (D-045 refined). Use `awaitCommand(opId)` only where the screen must wait for the server (start, end). Toasts from these screens pass `scope: 'classroom'` and name the class.
- Classroom flows with drafts (Start/End Lesson, later S6–S8 multi-step screens) keep their draft in the classroom page's per-context state and are rendered with `key` = context (and lesson) id, so a draft never carries over to another class (D-054).
- Modules add data to the polled lesson state with `registerLessonStateContributor(key, { stamp, build })` (`server/modules/lessons/service.ts`): `stamp` goes into the ETag so a change in the module invalidates the 304, `build` fills `body[key]`. Contributors are exported from the module (usually `routes.ts`) and listed in its manifest's `lessonState`. On the client, modules add header rows and per-card extras to the student grid with the client manifest's `studentCardAddons` instead of editing `Dashboard.tsx`.
- Counter colours are keys (`COUNTER_COLOURS` in `shared/counters.ts`), never colour values: the UI sets `data-colour` and `app.css` maps each key to `--cc-counter-*` tokens. Card levels show number + pattern + word (`card.level.*`); add a new colour key as `--cc-counter-*` tokens (`COLOR_TOKENS`, derived in `themes/base.ts`) for every theme.
- The personal student page is a separate Vite entry (`student.html` → `src/client/student/main.tsx`, served at `/s`, D-085). It must not import the teacher app (router, module registry, outbox); shared display pieces live next to their module (e.g. `modules/goals/shared.tsx`). Its language is per device (`localStorage`, English by default, UX-3/4).
- Per-device conveniences (active class, device sounds) use `localStorage` wrapped in try/catch; anything that must follow the teacher belongs in the user profile on the server.
- **Printing (S13b2, D-120).** Printable sheets are portalled to `<body>`, use a named `@page` rule and hide the rest of the page in `@media print`; anything that must scan or read on paper (QR codes, cut lines) uses the `--cc-print-ink` / `--cc-print-paper` tokens, which are black and white in every theme. Sizes on paper are in `mm`.
- **Evidence uploads (S13b2, D-119).** Add evidence through `modules/goals/EvidenceAdder.tsx` (it applies the media flags, prepares pictures with `lib/images.ts` and makes one item per file); do not add another file form. The server still re-encodes pictures and strips audio tags (`files/audioMeta.ts`) on every upload.
- **Class language (S13a, D-099).** Everything class-facing follows the class's `mainLanguage` / `secondLanguageEnabled` (`shared/classLanguage.ts`: `classLocales`, `displayLocale`, `pickLabel`), never the teacher's own interface language. The classroom screen wraps its content in an `I18nProvider` with the class locale (`useClassLocale`); the student page does the same from `StudentPage.language`. The language switch is shown only when the class has two languages. The student page and printed link cards use `studentPageLanguage(cls)`, which applies the class's optional student-page override (D-117). Teacher-editable class-facing labels are edited with `LangFields` (`ui/LangFields.tsx`) and `useEditorLocales(contextIds)`: one field per language the class uses, the main language first; a language that is off is never shown and its stored text is kept; text that falls back to the other language is marked "Needs translation". Display such labels with `pickLabel`/`pickText` in the class locale.
- **Classroom layout (S13a, D-103, D-139).** The lesson dashboard is a main column (dashboard region `top`, the student grid, then the `panels` in a grid under it) and a rail (`stage`, the timer, `actions` + End Lesson pinned at its foot; the rail ends at the bottom of the screen). A slot that has nothing to show returns `null` (never an empty card). Sizes come from the density variables on `.cc-classroom` (`--cc-card-*`, `--cc-rail`), not from fixed widths in module CSS; module panels must wrap in a column of about 19rem (`min-width: 0`) and start with `PanelHead` (`ui/Layout.tsx`). Device settings go into the top bar's Display popover, not into the bar. The module-off matrix in `e2e/classroom-layout.spec.ts` checks every new panel. Core pieces that belong to no module (the topic step, "Today's focus") use `module: null`.
- **Sound and celebrations (S13b, D-110).** Never create an `AudioContext` or call `speechSynthesis` in a component. Name the classroom event: `useThemeSound()('groupShuffle')` in components, `playEvent('tap')` in command senders; the SoundManager applies the class volume, mute, priorities and ducking. A new event goes into `SOUND_EVENTS`, `SOUND_PRIORITY` and `makeSoundPack` (with a `sound.<event>` name in en and tr). To tell the teacher why a screen is silent use `useSoundStatus()` (S14a, D-145), never the AudioContext; a control that unlocks audio in its own press handler carries `data-unlocks-sound`. Celebrate with `celebrate(message)` only after a teacher's action on this screen (never on load or a poll). The one exception is the Super Speakers board: a podium change celebrates only when the administrator turned board sound on (D-135). See docs/THEMING.md.
- **Student text (S13c, D-123).** Every new place where a student types free text calls `assertStudentText(ctx, { studentId, subjectId, teacherIds }, text, kind)` (`server/modules/textChecks/service.ts`) after the ownership checks, inside a write wrapped in `recordBlockedAttempts(ctx, () => tx(...))` so a blocked attempt is counted (never stored as text). Add the kind to `TEXT_KINDS` and show live hints on the client with `checkStudentText` from `shared/text/textQuality.ts`, passing the school's limits (`textLimits` on the goals section). Student text that is not prose (a link's address) gets the language check only: `assertNoRiskyWords(ctx, target, urlWords(url))`; student upload names go through `neutralStudentFileName`. Items a teacher hid (`hiddenAt`) are left out of student responses and are 404 for the student.
- **Words (S14a, D-144).** The user-facing word is "achievement(s)" / "başarı(lar)", never "badge" / "rozet" (guard test in `lint-rules.test.ts`); code names (`achievements.*` keys, `--cc-badge-*`, `BadgeArt`) keep their names.
- **Choice buttons (S14a, D-147).** A grid of choice buttons uses `repeat(auto-fit, minmax(min(100%, <n>rem), 1fr))` (never `auto-fill`, never a bare rem minimum), buttons `min-width: 0` with labels that may wrap; add the group to `e2e/button-groups.spec.ts`.
- **Avatars and badges (S13c, D-124, D-125).** Show students with the shared `Avatar` (`ui/Students.tsx`): it picks the photo (when allowed), the student's avatar from the classroom avatar directory, the generated avatar or initials. Never render a spec that did not pass `AvatarSpec`. Badges are drawn with `BadgeArt` and always show the tier as a word too. Art is original only (D-125).
- **Public sign-in pages (S13b, D-108).** Pages that work signed out (`/login`, `/reset-password`, `/invite`, `/signin-link`) are listed in `PUBLIC_PATHS` (`routes/guards.ts`). Tokens travel in the URL fragment, are removed from the address bar on load (`history.replaceState`) and are used only by a POST after a button press; a GET never consumes a token.
- **Classroom extension hooks (S13a).** `modules/classroomHooks.ts`: `registerTopBarSlot('quote' | 'weather', Component)` fills the top-bar slots (hidden when empty) and `onTimeUp(handler)` receives the timer's time's-up event (the S13b voice/chime) once per finished run for the whole page, even when two timers are mounted (the group screen). Full-screen classroom dialogs (`Modal size="full"`) make the rest of the page inert, so feedback and undo for actions inside them are shown inside the dialog, not as a toast.
