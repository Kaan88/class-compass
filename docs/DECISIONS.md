## S2 review fixes — 2026-11-07
- **D-027** — Enrolments are **date-aware** (refines D-021). An enrolment counts on local day D when `fromDate <= D < toDate` (open when `toDate` is null), with D = today in the class timezone (`enrolmentActiveOn`). Rosters, class student counts and levels use it, so a move or promotion dated in the future keeps the student in the old class until that day and the new class fills on that day. The move/promotion date (default: today, clamped into the target year) must lie inside the target class's school year (`MOVE_DATE_OUTSIDE_YEAR`); across years the old enrolment ends no later than the day after its own year ends (a promotion dated 1 September closes June's class on 1 July, not over the summer). New enrolments default to today clamped into the class's year. Moving students **out of** an archived class is refused like moving into one (`CLASS_ARCHIVED`; unarchive first). School years may not overlap, and a year's dates cannot change so that its terms or enrolment start dates fall outside it. Teachers may edit a student in their current class or one the student is scheduled to join; admin class/year filters show current and scheduled students. — Decided by Claude.
- **D-028** — Duplicate warnings (refines D-022) also run on **rename** (`allowDuplicateName` on the update) and include **deactivated** students (`candidates[].active = false`, `inactiveMatches` count), so a returning child is reactivated instead of getting a second identity. — Decided by Claude.
- **D-029** — Unused password-reset links are voided whenever the account's email changes, an admin resets the password, the user changes their own password, or the account is deactivated (D-015). SMTP on any port other than 465 requires STARTTLS (`requireTLS`), certificates are verified, TLS ≥ 1.2. — Decided by Claude.
- **D-030** — `seed:demo` hashes the demo passwords first and then writes the accounts and all school data in **one transaction**: a failed run leaves nothing behind and can simply be re-run (refines D-024). — Decided by Claude.

- **D-031** — **Classroom mode needs a PIN.** `/classroom` only opens for a teacher who has set a PIN; without one it shows "set a PIN first" with a link to the profile, because a classroom display that cannot be locked would expose the teacher area (PIN-1). The teacher/admin area relocks after **3 minutes without input** on the client (`CLIENT_IDLE_LOCK_MS`), on top of the server's sliding 5-minute window, and any 423 swaps to the lock screen and purges `['sensitive', …]` caches. A bfcache restore purges them too and re-runs the guards. — Decided by Claude.
- **D-033** — `seed:demo` accepts a fixed password (`CC_DEMO_PASSWORD`) **only when `NODE_ENV=test`** and only with ≥ 10 characters, for the Playwright server. Every other run keeps random passwords (D-024). — Decided by Claude.

- **D-035** — Outbox semantics (ENG-4, UX-10/11): a command is written to IndexedDB before it is sent; commands for one device are sent in order, at most one flush at a time (Web Locks across tabs); network/5xx/429/423 failures retry with exponential backoff (1 s → 30 s), 401 pauses the queue until the next sign-in, a server rejection moves the command to the needs-attention tray. **Retry from the tray re-queues it under a new opId**, because the server records rejected opIds and would otherwise replay the same rejection; dismiss drops it. The outbox is in place for S5, which adds the lesson commands that use it. — Decided by Claude.

## S3 review fixes — 2026-11-07
- **D-039** — **The outbox belongs to an account** (refines D-035). Every queued command stores the user id that queued it; only that account's commands are sent, counted, shown in the needs-attention tray or dismissable, and the batch carries `asUser` so the server refuses it with 409 `WRONG_ACCOUNT` when another account's cookie is in use. The owner follows the `me` query (sign-in, sign-out, 401, account switch). Other accounts' commands stay parked on the device until their owner signs in again; they are never sent under another session and never discarded automatically (UX-11). Commands rejected with `OP_ID_REUSED` (the server may already have applied them) or `UNKNOWN_COMMAND` can only be dismissed, not retried under a new opId. Command rejections carry a machine-readable `reason` that the tray translates; the server's English message is diagnostics only. — Decided by Claude.
- **D-040** — **Temporary passwords are enforced by the server.** While `mustChangePassword` is set, every `classroom`/`teacher`/`admin`/`account` endpoint answers 403 `MUST_CHANGE_PASSWORD` (after the PIN check, D-020), except endpoints marked `allowWithTemporaryPassword` (only `POST /api/auth/password`). `user` endpoints (me, logout, lock/unlock, preferences) stay open. The client sends the user to `/change-password` on that reason, and the outbox pauses instead of parking commands. — Decided by Claude.
- **D-041** — PIN lock screen details (refines D-032): the server returns the lockout as a relative `retryAfterMs` (plus `retryAt` for logs) and the client counts down from when it received the answer; wrong-PIN answers include `triesBeforePause` and `attemptsBeforeSignOut`, and from the first pause on the lock screen warns how many wrong PINs remain before the session is signed out. "Menu first" (PIN-4) also holds in other tabs: a sensitive area that has shown the lock screen and then sees an unlocked session goes to the teacher menu instead of revealing the deep-linked page. Toasts are sensitive unless raised with `scope: 'classroom'` and are cleared on lock, on entering the classroom and on sign-out; a toast with an active undo is never evicted by newer toasts (UX-9). — Decided by Claude.

## S5 — 2026-11-07
- **D-042** — **A lesson is created by one idempotent `lesson.start` command whose opId becomes the lesson id.** At most one active lesson per class+subject (partial unique index). Starting while one is running today returns `ok` with `{started: false, reason: LESSON_ALREADY_ACTIVE, lessonId}` and ignores the routine choice, so a double tap, a second device or a replay never creates a second lesson; the device simply resumes the running lesson (LES-2, UX-11). Its start-screen attendance is still applied (refined by D-053). — Decided by Claude.
- **D-043** — **Lessons belong to their local day.** A lesson still active after the end of its local day (class timezone) is no longer shown on the dashboard; the next start in that class+subject marks it `abandoned` (not ended, data kept, audited with reason `next_day`). Queued commands may still target it by id until then. Consequence: a lesson that runs across local midnight disappears from the dashboard at midnight. — Decided by Claude.
- **D-044** — **Commands name their lesson.** Every lesson/attendance command carries `contextId` and `lessonId`; the server refuses it with `WRONG_LESSON` when the lesson is not the active lesson of that context (or the envelope's context/lesson disagree with the payload) and with `LESSON_ENDED` when the lesson has ended. Commands queued for class A therefore never land in class B after a switch (LES-4). — Decided by Claude.
- **D-045** — **Polling with ETags.** `GET /api/classroom/contexts/:id/lesson` answers 304 to a matching `If-None-Match`; the ETag combines the lesson version (bumped on every change), the local date and a hash of the day's attendance rows, so a colleague's attendance change also refreshes the screen. The client (`callConditional`) polls every 5 s and the active-lesson list every 15 s; polling pauses while this device has unsent commands so a stale server answer never overwrites an optimistic change, and the lesson is re-read once the outbox is empty. — Decided by Claude.
- **D-046** — The classroom roster for lessons returns only classroom-safe fields plus attendance (no notes, no levels); attendance notes are teacher-area only. — Decided by Claude.
- **D-047** — **Routine snapshot.** The routine (name + stages) is copied into the lesson when it starts; later template edits, archives or default changes apply from the next lesson only (RTN-2). The built-in default routine (RTN-1, EN/TR names) lives in code (`builtin:default`), is always usable and cannot be edited, only copied. With the Routines module off, lessons start with an empty routine and stage commands answer `FEATURE_DISABLED`. — Decided by Claude.
- **D-048** — **The classroom timer is a core lesson tool**, not part of the Routines module: server-held state (duration, running, startedAt, remaining) shown from the server clock offset so all devices agree; when time is up the panel changes once (border, text, icon — no flashing) and one soft tone plays only if both the class and the device allow sounds. — Decided by Claude.
- **D-049** — **Attendance model.** Daily attendance is one row per student and local day, shared by every teacher of the class; any change is audited (`attendance_daily`, with before/after and actor, ACC-9). A lesson exception overrides it for one lesson only (effective = exception › daily › not recorded). "Not recorded" is never counted as present. The start screen proposes "present" for everyone without a record (a colleague's earlier record is kept) and sends only the changed rows (refined by D-053); "Everyone else present" never overwrites an existing record. — Decided by Claude.
- **D-050** — Classroom attendance commands need an active lesson (they are lesson-scoped and refused otherwise). Corrections for other days go through the teacher area (`/teacher/attendance`, PIN-gated REST endpoints) for any day inside the class's school year; history ranges are limited to one year. Teachers see exceptions only for their own lessons. — Decided by Claude.
- **D-051** — **End Lesson is a registry of steps.** The server keeps an ordered registry (`registerEndLessonStep`) whose validated inputs arrive in one `lesson.end` command; the core step is the reflection (rating 1–4 or none, optional note, order 100), so End Lesson works with every optional module off (LES-3). S7 adds the Secret Student reveal and outcome steps before it; the client mirrors this with `registerEndStepUi`. — Decided by Claude.
- **D-052** — **Dashboard slots and start steps are registries too** (`registerDashboardSlot`, `registerStartStep`, client side). A slot or step appears only when its module is enabled for the class+subject and has registered a component; until S6–S8 register theirs (assistant, counter, Secret Students, groups, homework) they are simply omitted — no "coming soon" placeholders on the classroom screen. — Decided by Claude.

## S6 Counters — 2026-11-07
- **D-057** — **Counter events are the source of truth** (refines D-004). A tap is a `counter.tap` outbox command whose opId becomes the event id, so a replay never counts twice. Each event stores its per-lesson `seq`, the class-local date and `weekStart` (Monday 00:00 in the class timezone, D-003) computed at write time, and a snapshot of the labels it was recorded with. Undo (`counter.void`) marks the event void and never deletes it. Lesson totals, weekly student counts, the class bar and the threshold state are always derived from the live (non-void) events. `threshold_crossings` records one row per upward pass over the limit: it opens when the bar reaches the limit and is cleared (reason `void`, `reset` or `limit`) when an undo, a class reset or a lower/higher limit takes the bar back below. The next pass opens a new crossing. — Decided by Claude.
- **D-058** — **Class reset keeps every event.** "Class reset" (`counter.resetLessonBar`, only when it is the chosen response) writes a reset marker (`counter_lesson_resets`, id = opId) with `afterSeq` = the last event seq. The bar counts only events after the latest marker; lesson totals and student counts are unchanged. A reset cannot be undone in S6. — Decided by Claude.
- **D-059** — **The threshold overlay plays once per crossing per device, and only while it is fresh.** The lesson state exposes the crossing number, count and time but never the event or the student behind it. The device shows the calm overlay (mascot animation once, nothing under reduced motion, no sound) only for a crossing less than 2 minutes old that this device has not shown yet (remembered in `localStorage`). In every other case, such as a reload, another device or a late poll, it shows the calm banner. The overlay and the banner never name a student. — Decided by Claude.
- **D-060** — **English preset and tap rules.** The English reminder counter ("Our English Time", "{count} / {limit} Turkish reminders", limit 10, levels 2/4/6, responses Back to English (default), No breaktime, Class reset, Practice challenge) is created automatically once per teaching context whose subject is English (subject name "English" or "İngilizce"), and only while the context has no counter row at all. An archived or edited preset is never recreated. Teachers of other subjects can add it from the teacher area. "Every term" falls back to the school year while terms are not modelled. Taps for a student marked absent or excused in that lesson are refused with `STUDENT_ABSENT`. The client ignores a second tap on the same student and counter within 700 ms and shows "Already counted – tap again to add another". The server does not apply this window, so two deliberate taps always count. — Decided by Claude.

## S7 Secret Students, Daily Assistant — 2026-11-07
- **D-062** — **Secret Student rotation and eligibility** (SEC-1, SEC-2, SEC-4, SEC-7; refines D-010). A draw chooses the class setting (default 2, 1–10, stored in the context's module config) from the students **present or late** in that lesson (effective attendance). "Not recorded" is not in the room, as in D-049, so the Start Lesson screen (everyone present by default) is the normal way in. With the Attendance module off, everyone enrolled is eligible. Order: fewest **counted** selections in this class+subject this school year, then the longest since the last one, then a random order. *(Amended by D-068: the tie-break is seeded with fresh server-side randomness, never with the round id.)* **Counted:** sealed, revealed and unrevealed-abandoned selections (D-010). **Not counted:** selections withdrawn by a confirmed redraw or because the student was marked absent, because that student never had the turn. Fewer eligible students than requested chooses everyone eligible and records `NOT_ENOUGH_ELIGIBLE` (or `NO_ELIGIBLE` for 0). A second draw returns the existing round unchanged (idempotent, never silently re-drawn), and only `secret.redraw` with `confirm: true` replaces it. A property test checks that students present every time differ by at most one selection. — Decided by Claude.
- **D-063** — **Daily Assistant rotation and weekly plan** (AST-1, AST-2). There is one assistant per class+subject and local day, shared by every lesson that day. A week's plan is stored as rows: the current week is generated on first use, other weeks when the teacher asks. The plan is never regenerated silently. Order: fewest effective turns this school year, counting planned future days too, so consecutive weeks stay fair, then the longest since the last turn, then the name in **Turkish collation** (UX-5). There is no randomness, so the same inputs give the same plan. "Plan again" (with confirmation) changes only future days still `planned` of an **unannounced** week. An announced week answers `PLAN_ANNOUNCED` and can only be changed day by day (swap, set assistant). School days (default Mon–Fri) live in the context's module config. Responsibilities are editable EN+TR labels (four defaults); removed ones are archived, never deleted. — Decided by Claude.
- **D-064** — **Secrecy boundary for Secret Students** (SEC-3, D-007). Only `server/modules/secret/` (and the schema) may touch `secret_selections`, enforced by `tests/server/secret-boundary.test.ts`. Before the reveal, everything that leaves the module is a count: the polled lesson state (`selectedCount` is fixed at draw time), draw/redraw results, the ETag stamp, and the draw/redraw audit entries, which record counts only. A chosen student marked absent is withdrawn and replaced inside the attendance transaction (through an attendance listener), with **no audit row, no lesson version bump and an identical attendance response**. The reveal audit records the selection ids and replacements. `tests/server/secret-leak.test.ts` compares every GET response and ETag as the teacher, the admin and another teacher before and after swapping the sealed students in the database, and they must be identical. End Lesson always reveals when the module is on (the teacher may reveal earlier inside the step). A round left unrevealed because the lesson was abandoned or the module was switched off is closed as unrevealed-abandoned by a lesson close hook and is never shown as selected. The classroom may read a reveal only on the lesson's own day; history is teacher-area. — Decided by Claude.
- **D-065** — **Assistant absence carry-forward** (AST-4, AST-5). When today's assistant is marked absent or excused (daily attendance, today only), the earliest later day in the plan whose assistant is in class today takes today's turn. The absent student takes that later day (`swapped`, reason `carry_forward`), **even when the week is announced**, because only those two students' days change and the absent student keeps the turn. If nobody is planned later, the next fair student in class does it (`replaced_absent`). The planned and actual students are always both kept. Turns count only the effective (actual) assistant, so a missed turn is not counted and is listed as "missed" in the history. Swaps and overrides refuse past days (`DAY_IN_PAST`) and students not in the class. Nothing is written in an archived class or school year. — Decided by Claude.
- **D-066** — **The weekly assistant schedule is classroom-safe** *(narrowed by D-068: only an announced week, this week or next)*. - **D-072** — **Grouping solver and default arrangements** (S8, GRP-1..4, GRP-6, GRP-8).
  - **Pure and deterministic.** `src/domain/grouping.ts` takes the students, mode, sizing, pair rules and a seed; the same input gives the same groups. A seeded draft (level order for level groups, a serpentine over levels for mixed groups) is improved by pair swaps with weighted costs (apart rule ≫ together rule ≫ spread of students without a level ≫ level quality), with a few deterministic restarts.
  - **Sizes.** "Number of groups" uses min(groups, students). "Group size" uses the number of groups whose sizes are closest to the target, with fewer groups on a tie: an odd class in pairs gets one group of three, and 7 students in teams of 4 get 4 + 3 instead of one team of 7 (S8 review fix; it was floor(students / size)). Group sizes never differ by more than one.
  - **Levels** are free text per subject (the S2 store). They are ranked by `orderedLevels`: the usual EN/TR word scales by their real order (Beginner/Başlangıç < Elementary < Intermediate/Orta < Upper-intermediate/Orta üstü < Advanced/İleri, also Low/Düşük < Medium < High/Yüksek), then every other label in natural order (`A1 < A2 < B1`, `2 < 10`). The Levels tab says which formats are understood and shows the order that will be used, live as the teacher types (S8 review fix: labels were sorted alphabetically, so "Advanced" ranked below "Beginner"). A per-class ordered level list (a picker) was not added; it would need a new table and is listed as a known gap. A student without a level is "not assessed" and is spread evenly over the groups in both modes.
  - **Unsatisfied rules** are stored with the arrangement and listed in the teacher area with a reason: ONE_GROUP, GROUP_TOO_SMALL, CONFLICTS_WITH_APART, NOT_POSSIBLE_WITH_OTHER_RULES, NO_ARRANGEMENT_FOUND, or ARRANGED_BY_HAND after a manual edit. When the swap search leaves an 'apart' rule broken, an exact backtracking search over the students the 'apart' rules name decides whether the rules can be met with these sizes (and starts from such an arrangement if so). NOT_POSSIBLE_WITH_OTHER_RULES is only reported when that search proved it; if the search hits its step limit the softer NO_ARRANGEMENT_FOUND is used (S8 review fix; checked against brute force for small classes).
  - **Defaults.** The five default arrangements (two level-based, three mixed) are created once per class+subject, the first time grouping is used while the class is writable **and has students** (audited). While the class is empty nothing is created, so the defaults never start with zero groups; a default saved empty by the earlier version is generated again on the next read (keeping its names and seed). Archiving a default never brings it back. Generating again keeps the group names and icons by position, so a teacher's renames survive.
  - **Neutral names (GRP-7).** Arrangement names are shown in the classroom picker, so the defaults are "Three groups", "Pairs A", "Teams A", "Teams B", "Pairs B" (TR "Üç grup", "İkililer A", "Takımlar A", "Takımlar B", "İkililer B"); the teacher area shows the type beside the name, and the name fields say that the name is shown in class. Level groups are built in level order and then put in a seeded random order, so the first group ("Foxes") is not always the lowest band. The classroom scan also fails on "Level"/"Seviye" in any classroom body (S8 review fix).
  - **Edits.** Teachers can change type and size (the groups are generated again), move students, rename groups, set optional roles and save the result as a new arrangement ("custom" mode). Students who have left the class are taken out of the editor (with a notice), and on save the server drops saved members who have left (other students outside the class are still refused); students of the class in no group are listed under "Not in a group" and can be moved in (S8 review fix). Every write carries `expectedVersion` (409 VERSION_CONFLICT) and is audited. Pair rules are archived, never deleted; their private note is never written to the audit log (only `hasNote`).
  - Decided by Claude.

## S9 Files, import, OCR — 2026-11-07
- **D-076** — **Uploads and file serving** (S9, STU-8, D-014).
  - **Storage.** A `files` row per upload. The bytes live under `DATA_DIR/uploads/xx/yy/<uuid>` (random key, no extension, never the client's name); an image thumbnail is stored next to it as `<key>-thumb`. The original name is kept only as cleaned display text for `Content-Disposition`.
  - **Pipeline.** `@fastify/multipart` (one file, few small fields) streams the part to `uploads/tmp` with a hard size limit per kind (image 10 MB, document 20 MB, audio 25 MB, student list 20 MB; `FILE_TOO_LARGE`). The type is sniffed from the content (`file-type`) and checked against the kind's allow-list; the client's MIME type and file extension are never trusted. Content without a signature is accepted only as plain text: no NUL bytes (unless UTF-16), few control characters and **no markup** (`<html`, `<script`, `<svg`, `<?xml`…), so SVG, HTML, XML and scripts are always refused (`FILE_TYPE_NOT_ALLOWED`). A CFB container is accepted only as an Excel 97–2003 workbook (Workbook/Book stream).
  - **Images** are decoded and re-encoded with `sharp` in the same format (auto-rotated, EXIF/GPS and all other metadata dropped, at most 2560 px, decoder pixel limit 50 MP) plus a 320 px WebP thumbnail. A polyglot (an image with appended HTML) therefore loses the extra bytes.
  - **Quotas.** Per student (`UPLOAD_STUDENT_QUOTA_MB`, default 100) and for the whole server (`UPLOAD_GLOBAL_QUOTA_MB`, default 10 240) over files not deleted, checked in the same transaction that inserts the row (409 `QUOTA_STUDENT` / `QUOTA_GLOBAL`); the stored bytes are removed when the insert is refused.
  - **Serving.** Only through `GET /api/files/:id` after the policy check (admin: any; teacher: own uploads, or files of a student they currently teach, never someone else's student list; everyone else 404, so ids do not leak). Responses carry `Content-Security-Policy: sandbox; default-src 'none'`, `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`, `Cross-Origin-Resource-Policy: same-origin`; images and audio inline, everything else `attachment`; Range requests for audio only (416 on a bad range).
  - **Media flags (D-014).** Evidence photos/audio/documents and student photos check `getMediaPolicy` on the server (403 `FEATURE_DISABLED`, reason `MEDIA_DISABLED`), and the UI only shows the controls when the flag is on. Student lists (`import_source`) are not media and are always allowed.
  - **Endpoints with a non-JSON body** are still declared in contracts and registered with `rawRoute()` (`lib/http.ts`): the access class is enforced before the body is read, the input is parsed from path and query, and the endpoint is part of the permission matrix.

- **D-078** — **Student list importer** (S9, IMP-1..6, D-013).
  - **Access.** The endpoints use the `account` class (PIN-gated in classroom mode). Teachers import into classes they teach (`assertTeachesClass`) and only see their own batches while they still teach the class; admins import into any class. The class must be writable (archived year = read-only).
  - **Workflow.** Paste or upload (`kind=import_source`) → draft batch with rows (`import_batches`, `import_rows`) → preview with field mapping, flags and decisions → commit → report → optional revert. Rows keep the raw cells, page and OCR confidence; rows edited by hand are not re-parsed when the mapping changes.
  - **Parsing.** e-Okul first: a header row is found by EN/TR labels ("Öğrenci No", "Adı", "Soyadı", "Adı Soyadı", "Sınıfı/Şubesi"…); title rows, page numbers, footers and headers repeated on every page are kept as ignored heading rows; merged-cell drift is corrected. Without a header, columns are inferred from content (running index vs student number vs names vs class labels). CSV/TXT encoding: BOM → UTF-16 without BOM → strict UTF-8 → Windows-1254 (a notice says which).
  - **Names (IMP-3).** Names are kept whole and only title-cased with Turkish rules. Given names and surname are split **only** when the list has separate columns; the importer never guesses which word is the surname.
  - **Flags.** `low_confidence` (OCR < 75), `duplicate_in_file` (all copies flagged, later copies skipped), `possible_match`, `number_match`, `missing_name`, `missing_number`, `heading_ignored`, plus two not in the brief: `number_elsewhere` (the number belongs to a student the teacher cannot see: skipped, and nothing about that student is shown) and `class_mismatch` (the list's class column names another class: skipped by default).
  - **Matching (IMP-4).** The same student number = the existing student (suggested `match`). A similar name without a number match (Turkish folding, word order, Levenshtein; score ≥ 0.85) is a `possible_match` with up to three candidates and **must be decided by the teacher**; committing with open choices is refused (409 `IMPORT_DECISIONS_NEEDED`). Names are never merged silently. Bulk "add all / skip all" exists for the open choices.
  - **Re-import (IMP-5).** Matched students are never changed or duplicated: already in the class → nothing; in another class this school year → not moved (reported); not enrolled this year → enrolled here. A missing student number is filled in only when the teacher ticks it for that row, and never when another student has it.
  - **Commit.** One transaction; each added row runs in a savepoint, so one failing row is reported (`failed` + reason) without losing the rest. New students go through `createStudentInClass` (reason `import`, `createdByImportBatchId`).
  - **Revert (IMP-5, DAT-5).** Type-to-confirm in the UI, `confirm: true` on the API. A student the batch created is deleted only when nothing references it (checked by deleting inside a savepoint: any foreign-key failure, another enrolment, or a reference in the grouping/assistant JSON columns counts as history); otherwise the student is deactivated and the row says so. Enrolments the batch opened for existing students are removed (no history) or closed. Numbers it filled in are cleared if unchanged since. Every step is audited (`import.revert`, `student.remove_imported`, `student.deactivate`, …).

  - **Same name in the file (IMP-2).** The same name with two different student numbers is two children: both rows are added and flagged `same_name_in_file`. The same number, or the same name where at most one copy has a number, stays a duplicate (later copies skipped).
  - **Same name outside the teacher's classes (D-022, ACC-4).** The importer now also checks folded names (and word order) of students the teacher cannot see; a hit is the flag `name_elsewhere` without any detail about that student and needs the teacher's choice before commit (`IMPORT_DECISIONS_NEEDED`), like `possible_match`.
  - **Numbers (IMP-4).** List positions are recognised when they start at 3 or less and go up mostly by one (gaps of 2–3 and page restarts allowed), also as "N - name"; otherwise the number is a student number. A number match whose name similarity is below 0.85 is flagged `number_conflict`, and a number match read by OCR with low confidence, both need the teacher's choice. Skipped rows never need a choice.
  - **Re-import (D-027).** Whether a matched student is already in the class or in another class this year uses the date-aware live enrolments (`liveEnrolmentsOf`), never `toDate IS NULL` alone.
  - **Revert (IMP-5, ACC-4).** A created student who has since moved to another class (any other live enrolment) is never deactivated by the revert: only the batch's own enrolment is closed if still open, and the row reports `moved_elsewhere`. An enrolment opened for a matched student is deleted only when nothing references the student in the class: attendance, lesson exceptions, counter events, Secret Student selections (via a boolean helper of the secret module), assistant duty (planned/actual), pair rules, homework marks and mark changes, the grouping/assistant JSON columns, and levels or files recorded since the enrolment was created; otherwise it is closed. A test compares the list with every table that has a foreign key to `students`.
  - **Spreadsheets (STU-8).** Workbooks are parsed with `sheetRows` (2100), the range is shrunk to the cells that exist and clamped to 60 columns, at most 20 sheets are read and reading stops once 2000 rows are collected, so a tiny file declaring `A1:XFD1048576` cannot block or exhaust the server. Parsing still runs on the main thread (a worker with a timeout, as for OCR, is open).
  - **Photos (CRD-1).** Deleting a file through `DELETE /api/files/:id` that is a student's current photo also clears `students.photoFileId` (audited `student.photo_remove`); the Avatar falls back to initials when an image fails to load.

## S10 Goals, evidence, student links — 2026-11-07
- **D-083** — **S10 housekeeping** (refines D-072, D-079, D-081).
  - **Unassessed spread (GRP-3, D-072).** The intermittent failure of the property "spreads the unassessed bucket evenly" was a solver bug, not a wrong property: an exhaustive run over the property's input space (2–30 students, 0–n without a level, 1–6 groups, both modes) found 72 mixed-mode cases such as 10 students, 4 without a level, 4 groups → 2,2,0,0. The swap search's cost `max − min − 1` is flat for the single swap 2,2,0,0 → 1,2,1,0, so the search stopped. The cost is now the sum of squares of the per-group counts (minimal exactly when the counts differ by at most one, and lowered by every swap towards that). The grouping property tests run with a fixed fast-check seed (`FC_SEED` overrides it; fast-check prints the seed and the counter-example on failure), and the exhaustive grid is a regression test.
  - **Parsing in a worker (D-079, D-081, STU-8).** Workbooks, Word and PDF files are parsed in a worker thread started for each file (`parsers/runParser.ts`) with a time limit (`PARSE_TIMEOUT_MS`, default 30 s, answer 409 `PARSE_TIMEOUT`) and a 512 MB heap limit; the thread is always terminated afterwards. Plain text is still decoded on the main thread (cheap and size-capped).
  - **Open import choices (IMP-4, D-081).** A row that needs the teacher's choice shows "Choose" in its decision menu instead of the suggestion, so choosing the suggested option is a real change (before, the menu showed "Existing student" and picking it again did nothing). The e2e import test was stale since D-081 (a number match with another name needs a choice) and now makes that choice.
  - Decided by Claude.
